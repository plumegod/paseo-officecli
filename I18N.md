# Runtime internationalization contract

## One pipeline, two presentation scopes

`shared/locales.ts` assembles all four resources from English-first tuples, including `shared/error-messages.ts`. SDK `defineTranslations` packages those same resources locally; no network translation service or new runtime dependency is used.

1. **Plugin-owned surfaces** call `useOfficeTranslation()`. The public SDK `useTranslation(messages)` subscribes to Paseo's effective locale. Exact supported locales use the SDK translator. Region/script normalization and the manual plugin override use the small interpolator over the **same resources**, because the SDK intentionally overrides `options.lng` with the host locale. Do not pretend `t(..., { lng })` is a plugin setter.
2. **Host-owned titles** use `messages.message(key, values)` at registration, never a pretranslated string. Paseo resolves these in its presenting client's language. Manual plugin language does not change host menus or add zh-TW to Paseo.
3. **Plugin diagnostics/errors** travel as `OFFICECLI_MESSAGE:` plus JSON `{ code, values }` in string RPC fields/Error.message. The locale-neutral code and parameters survive RPC serialization. Render through `display` at the client. Explicit `nested()` composes plugin diagnostics; ordinary `detail` values stay literal, including strings that resemble message envelopes. Never replace words inside official output.

Adding text: add a semantic key and four complete translations, keep interpolation names identical, then use `t("key", values)`, `messages.message("key", values)`, or `message("key", values)` as appropriate. English missing-key fallback is tested, but missing translations fail the completeness gate and are not a release strategy.

## Client preference and normalization

- Settings → OfficeCLI → Language: Follow Paseo (default), 简体中文, English, 繁體中文, 日本語. Language names are autonyms.
- The preference uses the standard Web Storage API under `paseo-officecli.language.v1`, scoped to this browser/desktop client's origin and this plugin ID, not to a daemon or workspace. Same-client panels share a module store and `useSyncExternalStore`; `storage` events synchronize other same-origin windows. Refresh restores the saved choice. Unavailable/denied storage shows a translated persistence error and keeps the current choice in memory; it does not fall back to daemon settings or private host storage APIs.
- This persistence path targets Paseo's desktop/web plugin surfaces. Native mobile has no Web Storage guarantee and already does not support the Office preview; persistent manual selection on such clients is not claimed.
- Follow mode never reads `navigator.language`: explicit Paseo choice wins. en-* → en; ja-* → ja; zh-Hans → zh-CN; zh-Hant → zh-TW. Explicit script wins over region. zh-TW/HK/MO → zh-TW, zh-CN/SG and bare zh → zh-CN; unrecognized tags → en. Traditional Chinese must never silently map to Simplified Chinese.

## Data and lifecycle boundaries

Do not translate official command names/flags, JSON drafts, stdin/stdout/stderr, CLI/OS/SDK raw details, document text, paths, or official HTML/watch pages. `PreviewFrame`'s surrounding accessible title is plugin text; its document is not. Snapshot instructions for the receiving agent use a stable English catalog entry; snapshot content and count metadata are data and do not change retrospectively.

Locale updates only rerender labels. No locale in document/job query keys, React component keys, execution callbacks or watch lifecycle effects. The watch toolbar label effect may depend on locale; its lease/frame/message-listener effect must not. Do not regenerate the official page/bridge or close a resident to change language. The authenticated iframe message channel may update the bridge's three plugin-owned transport-error labels in place; it does not translate official HTML or rerun its scripts. Do not clear argv/stdin, settings drafts, selection, job ID, outputs or confirmation state.

## Merge gates — no bypass

- `tests/i18n-policy.test.mjs` walks shipped TS/TSX source recursively, including new files. It rejects literal JSX text, text/accessibility props, plugin error copy and prose outside the catalog, regardless of whether it is English or CJK. Embedded watch/preview scripts are parsed and scanned rather than exempted as complete files.
- The small technical token allowlist is only for protocol syntax/internal details, not UI text. Never add a phrase there to make a feature pass. Resource modules may contain translations, not UI components or alternative stores. Do not move UI prose to unscanned assets or dynamically assemble it to evade the AST check.
- Catalog keys, nonempty four-language entries and interpolation names are checked. Public SDK resources are also validated when `defineTranslations` executes. The English SDK resource retains literal types for interpolation checks.
- `tests/i18n.test.mjs`, client and watch tests verify normalization, fallback, persistence, host/manual scopes, deferred host titles and state/lease preservation. Existing command/security tests still verify passthrough and process boundaries.
- `.github/workflows/check.yml` runs typecheck and all unit/policy tests on pull requests and pushes. Repository maintainers should make **Checks / typecheck-and-test** a required protected-branch check and require review for policy/catalog changes. Branch protection is a GitHub repository setting, not something this source change silently enables. No static check can prove all future dynamic text flows or prevent a maintainer from deleting the check; the review contract also applies.
